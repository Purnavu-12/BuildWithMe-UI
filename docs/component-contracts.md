# Component acceptance contracts

Current review: 2026-10-05. All 55 designs have framework-native sources and complete distribution closures. All 165 sources remain **provisional** until browser acceptance passes. The browser suite is authored for Chromium, Firefox, and WebKit, but was not run because local browser permission is blocked.

For each source, verify declared input changes, event payloads, composition, keyboard focus and keys, accessible labels, state transitions, theme isolation, reduced motion, pause/replay, unmount cleanup, and recovery. Tests in component-contracts.spec.ts cover native default interactions and deterministic dark/light captures at 360px and desktop. Custom-input, callback-payload, snippet/slot composition, hidden-tab cleanup, and recovery scenarios require the full consumer behavior review before marking verified.

Non-applicable capabilities must have a reason: a decorative field has no keyboard action; a source without declared callbacks emits no public event; a source without children/slots has no composition contract. Pure visuals without an async/error path do not need an artificial recovery control. Pointer effects must preserve readable content without a pointer. Host preview loading, retry, and clipboard recovery remain applicable independently.
