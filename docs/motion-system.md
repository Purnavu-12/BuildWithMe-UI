# Motion system

Motion explains how a source idea becomes a usable component. It never blocks reading, navigation, or installation.

## Ownership

- CSS: local hover, focus, simple state, and fallback visuals.
- Motion: scroll progress, chapter activation, springs, and React DOM transforms.
- Anime.js: isolated SVG paths and code-line sequences with explicit cleanup.
- React Three Fiber: the optional constellation canvas only.

No element may be driven by two engines. New animations must name their owner during review.

## Chapters

Signal begins with one luminous source glyph. Constellation expands it into registry-derived nodes and product domains. Translation separates the system into React, Vue, and Svelte. Ownership resolves it into npm, source registry, and copy-code paths. Open Orbit returns to authorship, provenance, and contribution.

## Fallbacks

The server renders every heading, paragraph, link, command, and chapter miniature. The SVG/CSS constellation is visible before hydration and remains final for reduced motion, mobile, touch-constrained layouts, save-data, low-power detection, and canvas failure. The canvas is `aria-hidden` and no essential action occurs inside it.

## Performance budgets

- No hero layout shift; the visual stage reserves its dimensions.
- Three.js stays outside the server and initial content path.
- One instanced node mesh, shared materials, and one buffered line network.
- Canvas rendering pauses when the story is off-screen or the page is hidden.
- Later chapters use content visibility where appropriate.
- Only the active component preview loads; Vue and Svelte runtimes do not enter the homepage bundle.

Standalone Vue and Svelte previews are generated as separate Vite entry graphs. Each component is a dynamic chunk, mounted inside an iframe only on its framework route. Host controls cross the boundary through the documented preview protocol; pause uses a runtime-wide animation state and replay remounts the selected component.
