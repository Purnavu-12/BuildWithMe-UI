# BuildWithMe UI

**Build the interface. Keep the source.**

BuildWithMe-UI is an open-source component ecosystem served by one Next.js application. Its 55 designs ship as 165 React, Vue, and Svelte framework sources. Install framework-specific source for ownership or copy the code directly. Package builds exist for release verification, but the packages are not yet published to npm.

The **Kinetic Playground** uses the Center Stage direction: charcoal and warm paper, lime, cyan, and coral, with an interactive Interface Engine. Assemble, Explore, and Translate change its geometry. Five native-scroll chapters connect the engine to working components, real framework runtimes, complete source files, and contribution paths. Motion owns component DOM transitions, Anime.js owns scoped SVG timelines, and React Three Fiber owns one optional desktop canvas. Mobile, reduced-motion, save-data, and WebGL failure retain the server-rendered story and SVG presentation.

## Your first contribution

New here? Start with [FIRST_CONTRIBUTION.md](FIRST_CONTRIBUTION.md). A documentation, copy, or small UI fix takes one branch and one relevant check. You do not need to know React, Vue, Svelte, and the registry to help.

## Start locally

Requires Node.js 22+ and pnpm 10.28.1.

```sh
pnpm install
pnpm dev
```

Open `http://127.0.0.1:3000`. The dev command generates the registry and isolated Vue/Svelte preview runtimes before starting Next.js.

## Install components

Every component page provides the currently available source command:

```sh
pnpm dlx shadcn@latest add https://build-with-me-ui.vercel.app/r/react/magnetic-button.json
```

The package publication folders are generated with `pnpm packages:build` and remain untracked until a release is prepared. The site does not present npm commands as available until a real release is published.

## Add a design

```sh
pnpm component:new signal-card data-display css
pnpm registry:validate
pnpm check:quick
```

The scaffold creates four authored files: a typed manifest and React, Vue, and Svelte sources. Registry artifacts, source maps, discovery records, and preview import maps are generated by `registry:build`; isolated framework runtimes by `previews:build`; package outputs and their README files by `packages:build`. The root README and public handbook are authored documentation.

See [CONTRIBUTING.md](CONTRIBUTING.md), [architecture](docs/architecture.md), [design system](docs/design-system.md), and [motion system](docs/motion-system.md). Coding tools use the canonical [agent guidance](AGENTS.md); human contributors do not need it.

## Quality commands

- `pnpm check:quick` runs lint, types, unit tests, and registry validation. This is the single automatic CI job on pull requests and main pushes.
- `pnpm check` validates formatting-independent code quality, types, tests, the registry, the Next.js production build, and all three package outputs.
- `pnpm test:e2e` verifies the discovery journey, accessibility, responsive layouts, reduced motion, and public registry endpoints.
- `pnpm test:install` packs tarballs, compiles all 165 installed source closures, and builds clean Next.js, Nuxt, and SvelteKit consumers that import every package export.

The full build, browser screenshots, and package installation suites are optional local checks for changes that need them. CI does not run browser matrices, pack packages, upload artifacts, publish to npm, or deploy. Package publication is manual; npm remains unpublished.

The selected framework in the component workbench is controlled by the `framework` query parameter (`react`, `vue`, or `svelte`). It determines the preview, usage examples, source files, and installation instructions. Catalog thumbnails always use React previews; selecting a framework carries that selection into the workbench.

For Vue, install the source files in your configured components directory. For Svelte, place the generated `components/buildwithme` directory under `src/lib` so the `$lib` imports resolve correctly. Preserve all delivered helper files, stylesheets, `LICENSE`, and notice files when copying a component.

Compilation and registry validation do not certify browser behavior. See [readiness](docs/production-readiness-plan.md) for fresh results and outstanding browser review.

## Configuration

Copy `.env.example` to `.env.local` when you need to override the canonical production site or repository URL.

Run `pnpm env:validate` in the production environment before deploying. It rejects missing, invalid, non-HTTPS, and localhost public URLs.
